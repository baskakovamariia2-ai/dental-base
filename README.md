# Dental Base

Закрытая мини-CRM стоматологической практики: пациенты, зубная схема (FDI), план лечения с индивидуальными ценами, история приёмов, расписание, склад и закупки.

**Стек:** Next.js 15 (App Router, Server Actions) · TypeScript · PostgreSQL · Prisma · Tailwind CSS.

---

## Запуск в интернете без терминала (Timeweb Cloud, серверы в России)

Понадобится компьютер (не телефон) и ~1 час. Платные только сервер и база, цена видна при создании.

### Шаг 1. Загрузить код на GitHub
1. Зарегистрируйтесь на https://github.com.
2. Справа вверху «+» → **New repository**. Название: `dental-base`. Обязательно выберите **Private**. Нажмите **Create repository**.
3. На открывшейся странице нажмите ссылку **uploading an existing file**.
4. Распакуйте архив `dental-base.zip` на компьютере, откройте папку `dental-base`, выделите **всё её содержимое** и перетащите в окно браузера.
5. Дождитесь загрузки и нажмите **Commit changes**.

### Шаг 2. Создать базу данных
1. Зарегистрируйтесь на https://timeweb.cloud и пополните баланс.
2. Раздел **Базы данных** → **Создать** → **PostgreSQL** (версия 16), регион **Москва** или **Санкт-Петербург**, минимальная конфигурация.
3. Включите автоматические **бэкапы** (резервные копии), если хостинг предлагает выбор.
4. Когда база создана, откройте её и скопируйте **строку подключения**. Она начинается с `postgresql://`. Сохраните её, она нужна на следующем шаге.

### Шаг 3. Запустить приложение
1. В Timeweb Cloud раздел **Apps** → **Создать** → тип **Backend** → **Dockerfile**.
2. Подключите аккаунт GitHub и выберите репозиторий `dental-base`, ветка `main`.
3. Регион — тот же, что у базы.
4. В **переменных окружения** добавьте:
   - `DATABASE_URL` = строка подключения из шага 2
   - `TZ` = `Europe/Moscow`
5. Порт приложения: **3000**. Нажмите **Запустить деплой**.
6. Сборка займёт 3–7 минут. Потом приложение получит адрес вида `https://...twc1.net` (HTTPS включён автоматически).

### Шаг 4. Первый вход
1. Откройте адрес приложения. Появится страница **«Первый запуск»**: создайте аккаунт владельца (пароль от 10 символов). Эта страница работает только один раз.
2. **Ещё → Сотрудники → Добавить сотрудника**: заведите аккаунт врача.
3. По желанию: **Ещё → Тестовые данные → Загрузить DEMO**. Потом их можно удалить одной кнопкой.
4. На iPhone: откройте адрес в Safari → «Поделиться» → **«На экран "Домой"»**. Приложение будет открываться как обычное.

### Обновления
Когда я пришлю новую версию, загрузите изменённые файлы в тот же репозиторий на GitHub (**Add file → Upload files**). Timeweb пересоберёт приложение сам, или нажмите «Деплой» вручную. Данные в базе при этом сохраняются.

## Для разработчика

```bash
cp .env.example .env          # указать DATABASE_URL
npm install
npx prisma db push            # создать таблицы
npm run dev                   # http://localhost:3000
```

Свой VPS: `docker compose up -d --build` (приложение + PostgreSQL + Caddy с HTTPS + ежедневный бэкап в `./backups`). Переменные: `POSTGRES_PASSWORD`, `APP_DOMAIN` в `.env`.

### Архитектура
- `prisma/schema.prisma` — схема БД. Пациент — центральная сущность: Appointment, Visit, Tooth, TreatmentItem, PatientPrice, PatientFile. Склад отдельно: InventoryItem → Purchase → Supplier.
- `src/actions/*` — серверные действия. **Каждое** начинается с `requireUser()` / `requireRole()`.
- `src/lib/auth.ts` — сессии: случайный токен в httpOnly cookie, в БД только SHA-256 хеш; пароли bcrypt (12 раундов); ограничение попыток входа.
- `src/lib/teeth.ts` — статистика пациента считается из зубной схемы, отдельно не хранится.
- Цена в плане лечения копируется при назначении, поэтому изменение прайса не меняет старые записи.
- Деньги хранятся в целых рублях.
- Файлы (этап 2): в БД только метаданные и `storageKey`, сами файлы — в S3-совместимом хранилище (Timeweb S3 / Yandex Object Storage) с временными подписанными ссылками.

### Безопасность
- Все страницы и действия проверяют сессию на сервере; middleware дополнительно отсекает запросы без cookie.
- Заголовки HSTS, X-Frame-Options, noindex.
- Секреты только в переменных окружения.
- Удаление пациента: сначала архив; полное удаление — только владелец.
